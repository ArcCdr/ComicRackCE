### Pass A: what the errors were, and what fixed them

134 errors in M0.3a. About 50 were `cYo.Common.Windows`/`Presentation` types, 36 in `NetworkManager.cs`, 15 in `Theme/ThemePlugin.cs`, 13 in `SingleInstance`/`ISingleInstance`, 11 in `Sync/*`. The rest were single-file gaps. All are resolved by the exclusions and replacements below. Once the declaration errors were gone, only two further rounds were needed: a missing `ItemViewConfig.SortKey`/`GrouperId` (3 errors) and the .NET 10 SDK WinForms analyzer `WFO1000` (48 errors; see below).

## Needs edit

**None.** Every pass A error was resolved with exclusions and `Replacements/` files. No file in the seven original project folders was edited.

## Added by M1.1

- **`mac/cYo.Compat.Forms`** (assembly `cYo.Compat.Forms`, namespace `System.Windows.Forms`): the types-only WinForms slice. `Shadow.props` references it in pass B only; pass A keeps the real WinForms.
- **Real files linked into `ComicRack.Engine.Core`** (`Sources.props`, folder `CommonWindows` in the project): `cYo.Common.Windows/Forms/ItemViewConfig.cs`, `ItemViewColumnInfo.cs`, `ItemViewMode.cs`, `ItemViewGroupsStatus.cs` (used by `ItemViewConfig`) and `GroupHeaderInformation.cs` (used by `ItemViewGroupsStatus`). None needs a control.
- **Removed:** the `ItemViewConfig` stub of `CommonWindowsTypes.cs`. The `IColumn` stub grew from 4 to 10 members, because `ItemViewColumnInfo` reads them.

## Added by M1.2a

- **`mac/cYo.Compat.Drawing`** (assembly `cYo.Compat.Drawing`, namespaces `System.Drawing`, `.Drawing2D`, `.Imaging`, `.Text`): the surface skeleton for the 47 `System.Drawing.Common` types of the inventory (one file per type in `Types/`). `Shadow.props` references it in pass B only. `cYo.Compat.Forms` references it too (`Cursor.Draw(Graphics, Rectangle)`).
- **`ImageFlags`** is in the shim although the inventory does not list it: the compiler inlines enum constants, so an enum used only as `ImageFlags.HasAlpha` never shows up (`HeifAvifImage.cs`).
- **Pass B only replacement** `ComicRack.Engine.Core/Replacements/PassB/PdfStorageProvider.cs` (the original is removed from the pass B compile; pass A still compiles it, so the inventory is unchanged). The original passes a `Bitmap` to `sharpPDF.pdfPage.addImage(System.Drawing.Image, ...)`; sharpPDF is a .NET Framework assembly bound to the framework's own `System.Drawing` types, which the stand-in (a different assembly) cannot satisfy. The replacement throws `NotSupportedException`; PDF export is not in the MVP.
- `mac/tools/drawing-coverage`: checks the stand-in against `inventory.json` (adapted from the M0.4 spike).

## Other changes to the shadow build

- `Shadow.props`: pass A suppresses `WFO1000` (the WinForms designer-serialization analyzer introduced with the .NET 10 SDK; it flags about 16 properties in linked sources and is not a compile gap).
- Each `Sources.props` (and the Plugins project file) compiles `Replacements/**/*.cs`; `Sources.props` of Common and Engine also hold the new exclusions.
- `mac/tools/census`: now also writes an "Errors per bucket" table and a raw `mac/artifacts/census/diagnostics.<pass>.txt` (git-ignored).
- `mac/tools/api-inventory`: new, see below.

## Limits of these numbers

- Pass B is still a lower bound: members used on a type that is currently unresolved are not visible until the type exists. The API inventory (read from the pass A assemblies) is the authoritative list of members.
- The API inventory covers only the three Core assemblies. Python scripts (D6) are outside this repository.
- `ItemViewConfig` now round-trips the full `ComicDb.xml` view settings (real file linked in M1.1, test `ItemViewConfigTests`). The `IViewableItem`/`IColumn` stubs are never serialized.
