Generated by `crcli script-scan --markdown` (P4.6b). Do not edit by hand: regenerate with `mac/scripting/scan-corpus.sh`. Only scan results are kept in the repository; the plugins themselves are downloaded into `mac/fixtures/plugins/` (git ignored) and are never run (`mac/scripting/corpus.md`).

This is the ranked implementation backlog of the Script UI Compatibility Layer (MACOS_NATIVE_PATH.md section 5.9): `type.member -> number of scripts that use it`. P4.7 generates the whole surface; P4.9 to P4.13 implement behaviour in the order of these tables.

## 1. How this was made

    mac/scripting/fetch-corpus.sh

- Surface read from: the reference assemblies of the Windows Desktop reference pack 10.0.13 (1111 types of `System.Windows.Forms*` and `System.Drawing*`).
- 3 paths of the checkouts are left out (build tools, tests, program assemblies kept for reference): `corpus-exclude.txt`.
- A *unit* is one script, assembly or HTML file; a *plugin* is the package it belongs to (a `.crplugin` file, a plugin folder, or a loose script). Scripts of the Python standard library that a plugin carries are units too (tier none); the plugin counts are the figures to read.
- Python is dynamic: an access on a value whose type the scan could not tell is counted in section 5, not in the member table. Assemblies are measured by member references of their metadata (a reference, not a call count).
